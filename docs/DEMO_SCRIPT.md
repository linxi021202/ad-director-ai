# Demo Script

## 3 分钟演示

### 0:00–0:30 产品定位

“AdDirector AI 把商品简报变成可交付的广告方案。它不是单一 API 套壳，而是包含策略、分镜、关键帧、主镜头、旁白、合成和失败恢复的工作流。”

### 0:30–1:20 生成链路

展示当前项目的真实参数：默认 40 秒、8 个镜头。

```text
DeepSeek -> Qwen-Image -> HappyHorse -> Remotion
```

DeepSeek 负责思考和结构化提示词；Qwen-Image 生成逐镜头关键帧；HappyHorse 只生成一个 5–7 秒主镜头；Remotion 按真实镜头时长合成完整广告。

### 1:20–2:10 可解释与恢复

打开模型 Trace：事件由服务端写入 `project.json`，页面刷新或从项目详情返回生成页后仍然存在。日志只包含阶段、状态、进度、耗时和脱敏错误码，不保存密钥或上游完整响应。

展示单张关键帧失败不阻断其他镜头、HappyHorse 可手动导入、主镜头可降级为关键帧动效。

### 2:10–3:00 成片

展示 Remotion 动态时间轴：镜头数量和帧数来自项目，不固定四段。默认 40 秒项目是 1200 帧；旧 18 秒项目仍按原时长渲染。最后预览或下载私有 MP4。

## 常见追问

**为什么只生成一个视频镜头？**

视频最慢且最容易失败。一个主镜头证明视频能力，其余镜头用关键帧和可控动效完成，既能交付完整广告，也保留明确的降级路径。

**返回生成页后为什么日志还在？**

事件保存在项目 `generationEvents`，会话 `workspace.json` 记录最近活动项目。生成页恢复项目后直接读取服务端事件。

**40 秒是否写死？**

不是。40 秒是新项目默认值；总时长始终来自镜头求和，15、20、30 秒和旧 18 秒项目继续按各自数据运行。
